Screen a library. Or screen them all.

AMDockVS is a distributed platform for structure-based drug discovery. Protein–ligand virtual screening today, with a docking layer built to take other campaign types as they land. Two flows share one project model: VS for libraries in the hundreds of thousands on a single workstation, HTPVS for millions, sharded across a local network or an HPC queue.

Platform

Two flows, one project model

Both share the same docking layer, the same engines and the same results table — what changes is whether the library lives in the project or streams past it.

VS

The library is the project

Ligands are rows in the project database: browsable, filterable, one click from a pose. Standardise, compute descriptors, cluster for diversity, dock a scope and read the results in the same table you imported into. The right shape for a few hundred thousand molecules on the machine under your desk.

Rows · full inventory · interactive

HTPVS

The library never enters the project

The import splits the library into uniform shards and materialises nothing. One shard is one unit of work, so a campaign fans out over cores, a lab network or an HPC allocation, and only promoted hits ever become rows — which is what keeps a ten-million-molecule run from filling the database it was meant to stay out of.

Shards · hit gate · resumable

The mode is read off the data, never declared: a project holds shards or it holds rows, and the interface follows. Docking engines, pocket detection, preparation and analysis are one layer below both — which is where other campaign types will plug in.

One project, the whole campaign. No exports between steps, no second project to keep in sync.

Tools

The toolchain, in one place

Diversity clustering

Fingerprints, BitBIRCH clustering and representative picking — cut the library before you spend a docking run on it.

QSAR

Descriptors, activities, datasets and models. Train on what you have, score what you don’t, keep both in the project.

Ligand preparation

SMILES to 3D conformers, MMFF minimization, protonation states, tautomers and torsion trees, applied across the whole scope.

Receptor preparation

From sequence to structure: homology or AlphaFold models, protonation at your pH, waters removed and charges assigned.

Binding site definition

P2Rank cavity prediction, residue selection, a co-crystal ligand, or a grid box you set by hand.

Docking engines

Vina 1.2.7, QuickVina2, GNINA — classical scoring and AI-based rescoring behind one interface.

Docking

Docking, re-docking and off-target docking against a second receptor — same inventory, same results table.

Virtual screening

Scope a set, dock it, rank it, open the pose — all in the table you imported into.

HTPVS campaigns

Shards as work units, dispatched over cores, a lab network or an HPC queue. Crashes resume; only hits are promoted.

Interactions

Contact maps and 2D interaction diagrams for the poses that survive — figure-ready, from the app or the CLI.
